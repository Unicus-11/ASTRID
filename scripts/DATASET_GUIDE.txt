============================================================
ASTRID DATASET GUIDE
============================================================

PURPOSE
============================================================

The ASTRID dataset is generated from SUMO traffic simulations.

Each scenario represents a different traffic condition and
sensor-observation condition.

The dataset is intended to provide:

    - traffic state
    - vehicle ground truth
    - GPS observations
    - CCTV observations

This allows ASTRID to learn/estimate traffic conditions from
partial and imperfect sensor information.


============================================================
WHAT KIND OF SCENARIOS ARE GENERATED?
============================================================

The scenarios represent different traffic conditions.

LOW
    lighter traffic

MEDIUM
    normal/moderate traffic

HIGH
    heavy traffic

VERY_HIGH
    very heavy / congested traffic

Within each demand level, the generator also changes:

    - traffic distribution between approaches
    - vehicle composition
    - turning behaviour
    - GPS availability
    - CCTV detection quality

Therefore two scenarios with the same demand level can still
be different.


============================================================
IMPORTANT: DEMAND VS ACTUAL TRAFFIC
============================================================

The scenario's total_vehicles represents the number of
vehicles scheduled to enter the simulation.

It does NOT mean that this many vehicles are simultaneously
present at every moment.

Vehicles:

    enter SUMO
        ↓
    travel through the network
        ↓
    leave SUMO

Therefore the number of active vehicles changes over time.


============================================================
MAIN SCENARIO VALUES
============================================================

1. Total vehicles

    total_vehicles = demand_rate

Example:

    high demand → 2100 scheduled vehicles


2. Vehicle-type allocation

    vehicles_of_type =
        total_vehicles × vehicle_distribution[type]

Example:

    2100 × 0.70 = 1470 cars
    2100 × 0.20 =  420 bikes
    2100 × 0.05 =  105 buses
    2100 × 0.05 =  105 HGVs


3. Approach allocation

    approach_vehicles =
        total_vehicles × approach_distribution[direction]

Example:

    2100 × 0.25 = 525 north
    2100 × 0.25 = 525 south

The actual generator uses controlled rounding so that
allocated totals remain consistent.


4. Movement allocation

For each approach:

    movement_vehicles =
        approach_vehicles × movement_probability

Example:

    north = 525

    straight = 525 × 0.50
    left     = 525 × 0.30
    right    = 525 × 0.20

Largest-remainder allocation is used so that:

    sum(movements) = approach_vehicles

and rounding does not create:

    sum(movements) != approach_vehicles


============================================================
QUEUE LENGTH
============================================================

Queue length is NOT generated by create_scenarios.py.

It is measured after the SUMO simulation runs.

A vehicle is considered queued according to the traffic-state
definition used by the sensor/state extraction code.

Therefore queue length is an observed simulation result,
not a scenario input.


============================================================
IMPORTANT: TWO VEHICLE POPULATIONS
============================================================

The dataset contains two different vehicle populations.

                         ALL SUMO VEHICLES
                                |
               +----------------+----------------+
               |                                 |
        INCOMING EDGES                       OTHER EDGES
         1i, 2i, 3i, 4i                intersection/outgoing
               |                                 |
               ↓                                 ↓
         TRAFFIC STATE                     GROUND TRUTH


TRAFFIC STATE
-------------

The traffic state counts vehicles currently on the four
incoming approach edges:

    1i
    2i
    3i
    4i

It is used to describe the traffic approaching the junction.


GROUND TRUTH
------------

Ground truth contains all vehicles currently present in SUMO.

It includes vehicles on:

    - incoming edges
    - intersection-related edges
    - outgoing edges

Therefore:

    traffic.total

and:

    len(ground_truth)

are NOT supposed to be equal.

A difference between these values is normally expected.


============================================================
QUEUE CHECK
============================================================

For each approach:

    queue <= vehicles

This should always be true.

Why?

Because queue is a subset of the vehicles currently on that
approach.

Therefore:

    queue > approach vehicles

indicates a data/logic error.


============================================================
GPS AND CCTV
============================================================

GPS and CCTV are observations, not complete ground truth.

GPS:

    only some vehicles have GPS depending on the scenario's
    GPS penetration.

CCTV:

    detects only vehicles within the simulated camera coverage
    and according to the configured detection probability.

Therefore:

    GPS count < total active vehicles

and:

    CCTV count < total active vehicles

are normally expected.


============================================================
GROUND TRUTH IS NOT A SENSOR
============================================================

Ground truth represents the actual simulation state.

GPS and CCTV represent imperfect observations of that state.

Conceptually:

    SUMO
      |
      ↓
    GROUND TRUTH
      |
      +----> GPS observations
      |
      +----> CCTV observations
      |
      +----> traffic state


============================================================
COMMON MISCONCEPTIONS
============================================================

1. "total_vehicles means vehicles present at every timestep."

    WRONG.

    It means vehicles scheduled/generated for the scenario.


2. "traffic vehicles must equal ground_truth vehicles."

    WRONG.

    Traffic state counts incoming-approach vehicles.
    Ground truth counts all vehicles currently in SUMO.


3. "queue length is an input from the scenario."

    WRONG.

    Queue length is measured from the simulation.


4. "GPS count should equal active vehicles."

    WRONG.

    GPS penetration is intentionally partial.


5. "CCTV count should equal active vehicles."

    WRONG.

    CCTV has limited coverage and imperfect detection.


6. "Two scenarios with the same demand are identical."

    WRONG.

    Approach distribution, vehicle composition, movement
    distribution, GPS penetration and CCTV detection can differ.


7. "A vehicle disappearing from traffic state means it vanished."

    WRONG.

    It may simply have left an incoming approach and moved
    through the intersection or onto an outgoing edge.


============================================================
VALIDATION
============================================================

Use:

    python scripts/validate_dataset.py \
        datasets/scenario_0002/sensor_dataset.json

The validator checks structural and logical consistency.

It should NOT require:

    traffic.total == len(ground_truth)

because these values represent different populations.


============================================================
KEY IDEA
============================================================

Scenario configuration
        ↓
SUMO simulation
        ↓
actual vehicle movement
        ↓
+----------------------+----------------------+
|                      |                      |
GROUND TRUTH       SENSOR OBSERVATIONS    TRAFFIC STATE
|                  GPS / CCTV             |
|                      |                  |
actual state       imperfect view        approach state
of SUMO             of reality            of junction


The dataset should always be interpreted according to these
definitions.
